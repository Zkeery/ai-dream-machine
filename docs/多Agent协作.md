# 多 Agent 自主协作

首页创建故事或漫剧在内部统一使用多 Agent 自主协作，不展示协作方式、机制说明或分工记录；旧草稿再次创建也使用该模式。已创建的历史作品保留原有模式，后端继续支持标准工作流以兼容旧项目；创建会话后模式固定。每个阶段仍需用户主动生成并确认后进入下一阶段。

## 执行与分工

`AgentRuntime` 包裹既有阶段执行器。v2规划模型只输出目标、摘要和最多2个资料研究问题；程序生成任务ID、角色和依赖，最后交给唯一的专业生成角色。未绑定资料时不安排检索；专业角色依阶段选择编剧、导演、视觉设计或制作。不同任务拥有各自工具观察、行动记录与依赖交付，模型自行决定下一行动。这里的独立是任务、上下文和决策独立，当前共用用户所选文本模型、同一进程，按依赖顺序执行。旧任务图保留兼容读取。

角色允许的工具由程序固定：研究 Agent 可查看输入、检索绑定资料和交付结论；专业 Agent 另可设置创作建议并调用一次当前阶段生成。模型不能执行任意代码、切换账号或调用其他阶段。检索资料只能提供内容依据，不得改变权限、预算或输出协议。专业建议通过上下文变量进入文本、图片及视频提示词，生成后清除，避免污染其他请求。

独立审稿 Agent 只检查已提供文本、结构及元数据，不能声称看过画面或听过声音。对剧本及两类分镜可提出一次自动改稿并复审；媒体只记录建议，由用户检查后决定是否重新生成。语音与合成的制作 Agent 可以检索和检查依赖并决定执行时机，不能擅改已确认的配音文本、音色及合成参数。

## 执行限制与费用

规划、工具选择、审稿属于短决策：对当前可选Qwen3.5模型显式关闭思考，输出最多2048 token，温度0.2；正式创作请求保留原参数。参数通过请求上下文隔离，避免污染并发创作。超时显示请求类型和等待上限，仍停止自动重发。2026-10-05真实用户请求曾在首个规划步骤到达180秒超时上限，本次配置优化经离线测试，不代表供应商响应时间已获得保证。

每任务最多6次行动，每阶段最多24次控制决策；控制模型结构化输出的解析重试、明确HTTP失败的有限重试仍沿用既有客户端，因此决策数不是实际HTTP调用数。模型调用均经过现有账号费用账本与预算预留。界面在创建前说明自主协作会增加文本用量与等待时间。不能把这次工程接入等同于成本或质量收益。

## 检查点与恢复

结构化回复校验失败时，有限重试会附带具体字段位置、错误类型和Schema，避免原样重复请求。合法任务图可由程序拓扑排序；内部任务ID允许描述性文本，但仍检查重复、缺失和循环依赖。已收到回复但格式不合格属于已知失败，保存校验摘要并清除待响应标记；与网络中断造成的结果未知分别显示。历史同类错误记录通过只读判定纠正恢复提示，不修改历史用量或产物。

数据库会话新增 `orchestration_mode`、`agent_runs`，旧库自动增列。每次决策和工具调用保存状态，执行链使用原始执行ID定位检查点，既有恢复快照继续检查模型、上游版本、文件与资料版本。媒体产物被检查点引用时保留，失败回滚不会误删。

恢复入口沿用原计划、已完成动作、创作建议及供应商任务序列。已收到但不合法的控制回复，以及有明确格式错误证据的文本生成，也可在没有媒体任务时显式继续；继续仍受输入快照和账号校验约束。成功生成后恢复不再次生成。控制模型请求发出但结果未保存时标记不确定并阻止重放，新的未知结果不能借用旧格式错误的证据放行。

专业生成成功即由程序完成交付，省去模型finish调用。审稿异常时保留产物，转为人工检查，不声称审稿通过。规划格式修复耗尽时采用透明的基础计划；网络未知不会触发该回退。真实供应商验证与离线结果分开记录，见[协作可靠性验收v2](Agent/协作可靠性验收-v2.md)。
