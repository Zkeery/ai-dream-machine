# AI造梦机 · 主项目说明与项目经历

更新：2026-10-04。本文用于项目展示、面试介绍和项目经历整理；产品要求以 [PRD](../PRD/PRD.md) 为准，运行状态以 [项目状态](../项目状态.md) 和带日期的验收证据为准。

**产品定位：AI造梦机是一款面向个人创作者和小型内容团队的 AI 视频创作与项目资产管理平台，围绕故事短视频和漫剧组织内容策划、剧本分镜、画面生成、配音合成与成片导出，并统一管理创作资料、角色、镜头、素材及版本。**

**验证状态：已完成本地环境的工程闭环及双链路真实样片验证，内容质量持续迭代。** 2026-10-04本轮后端357/357、前端69/69及类型/Lint/构建通过，运行新版本；故事与漫剧各1人1场景1集2镜头真实成片完成并在浏览器播放到结束。跨进程供应商续接、402后恢复及额度展示已验。视觉一致性、配音自然度、商业价值和多用户生产稳定性仍须分别评价，不能从工程成功直接推出。

可直接查看[项目说明HTML](主项目说明.html)、[双样片预览](../evidence/真实样片验收/样片预览.html)与[本轮验收证据](../evidence/真实样片验收/验收记录.md)。

## 一、项目背景：原来有什么问题，为什么做

### 1. 用户与场景

目标用户是希望持续制作剧情内容的个人创作者，以及需要验证选题和内容形式的小型内容团队。这是当前的目标用户定义，尚无大样本用户访谈或商业客户数据支持，不把目标人群写成已获得的用户规模。

| 使用场景 | 用户起点 | 要解决的问题 | 预期获得的结果 |
| --- | --- | --- | --- |
| 验证一个故事想法 | 一句创意、情节梗概或短篇故事 | 不知道如何拆成剧本、角色和可制作镜头；直接生成后难以判断哪里出了问题 | 默认一集的故事短视频，以及可检查的剧本、分镜、画面和版本 |
| 制作人物对白驱动的漫剧 | 剧情、人物关系和对白 | 静态漫画图无法直接成为可观看内容；对白、配音、字幕和镜头时长需要衔接 | 漫画镜头、角色配音、基础运镜和中文字幕组成的漫剧 MP4 |
| 修改已有作品 | 已有大部分满意的内容，只想改一句对白或一个镜头 | 不清楚哪些下游产物需要更新；全部重做会增加操作和调用成本 | 保留可用素材和历史结果，只更新选定内容及受影响的下游 |
| 延续设定、复用资料 | 角色设定、世界观、品牌材料或创作素材 | 多次生成时反复输入资料，结果来源和使用版本难以核对 | 按项目选择知识库、查看来源，复用本人素材，并由用户确认生成结果 |

### 2. 原问题与产品动机

从想法到成片，需要组织内容、画面、声音和剪辑多个步骤。用户不仅需要生成能力，还要决定顺序、搬运素材、保留成功结果，并在发生修改或失败时判断下一步。项目早期走查也暴露了主流程、快捷工具、作品和资料之间关系不够清晰的问题。

因此，产品首先解决创作过程的组织与操作负担：明确两条创作入口，把可确认的中间产物串成闭环，让用户能定位、修改和继续作品。使用 AI 的目的在于辅助完成内容与媒体生产，最终内容方向和发布质量由人判断。是否实际减少制作时间、降低单片成本，需要用相同任务和相同验收标准进一步测量。

### 3. 本期范围

- 故事短视频：创意 → 剧本 → 角色/场景 → 分镜 → 参考图 → 镜头视频 → 成片。默认一集，当前成片主要为视频拼接。
- 漫剧视频：创意 → 剧本 → 角色/场景 → 镜头对白 → 漫画镜头 → 角色配音 → 运镜字幕成片。当前为单集视频。
- 共用能力：账号隔离、作品库、素材复用、知识库、任务进度、历史版本和普通用户模型选择。
- 快捷工具：文艺短视频、角色动作短片、图片配音口播；服务于单次短视频需求，不作为漫剧阶段。

当前不把真实动作迁移、口播嘴型同步、完整故事配音配乐、普通界面完整首尾帧制作或生产级多人运行写成已交付能力。

### 4. 技术形态

当前使用 Next.js、React 与 TypeScript 构建创作前端，FastAPI 提供账号、作品、模型与生成流程接口，SQLite 保存项目、任务和版本状态，本地文件保存媒体产物。模型适配层接入文本、生图和视频服务；FastEmbed 与本地 Qdrant 支持创作资料检索，Edge TTS 与 FFmpeg 承担配音及媒体合成。它是有明确阶段和人工确认点的工作流，当前不是可任意规划任务的通用自主 Agent；本地单进程运行与生产级任务调度也需分开描述。

## 二、职责边界：个人主导与 AI 协作

本项目以个人主导、AI 协作为实际工作方式。没有证据支持外部研发团队、跨部门管理、商业客户交付或大规模用户研究等经历，不添加这些背景。

| 事项 | 个人主导的职责 | AI 协作与工程系统承担的部分 | 判断完成的依据 |
| --- | --- | --- | --- |
| 产品方向 | 定义主项目定位、目标用户、使用场景；决定故事与漫剧分成两条链路 | 整理问题、拆解方案、核对需求与代码的对应关系 | PRD、需求澄清和范围决策可追溯 |
| 交互与视觉 | 提出并选择视觉方向，审查首页、导航和创作路径，反馈具体改动 | 产出原型与页面实现，检查布局和交互 | 实际页面检查及验收记录 |
| 范围与优先级 | 确认本期保留的能力、默认参数、权限和模型选择规则 | 评估实现影响，补充兼容、失败和历史数据处理 | 需求规则与前后端行为一致 |
| 开发与集成 | 审查方案和阶段结果，决定是否继续扩展、修正或验收 | 辅助编写代码、接口、提示词、测试和技术文档，执行本地验证 | 可运行代码、请求合同与原始测试记录；不把 AI 生成代码描述为全部手写 |
| 质量验收 | 确认内容是否符合意图、视觉是否可用、功能是否满足需求 | 自动化检查结构、状态、权限、媒体格式及已知失败场景；整理待验项 | 工程测试与真实效果评价分别记录，不能互相替代 |

**工作方式中的人机分工：** AI 负责候选生成和重复性检查；人在剧本、分镜、素材选版和最终成片等节点检查并确认。系统保存选择、输入与历史版本；修改上游后标记受影响结果，由用户决定是否继续生成。对未知模型效果、资料不足或供应商异常，明确保留失败与待验状态。

## 三、六项核心职责：问题、动作与结果

### 1. 用户问题定义与需求范围管理

**问题：** 功能不断增加后，入口、主流程和辅助工具容易混在一起，难以说明用户为什么需要产品、从哪里开始、最终得到什么。

**动作：** 主导把需求按用户、场景、问题、过程和结果重写；确定故事短视频与漫剧视频双主链；明确默认一集、快捷工具用途、共用知识库，以及普通用户和管理员的权限边界。

**结果：** PRD 已形成可检查的阶段输入、产物、确认点和验收条件。漫剧作为独立视频链路，不再借用故事视频阶段名。该结果证明范围和需求结构更清楚，尚不等于已验证用户留存或产品市场匹配。

### 2. 创作流程设计与可控的人机协作

**问题：** 一次生成直接到最终结果，用户难以定位问题；局部修改可能使下游继续使用过期素材。

**动作：** 主导确认分阶段检查、编辑、选版和重新生成的交互规则；通过 AI 协作接入产物版本、选用版本、依赖关系和失效提示；支持按角色、场景或镜头定向更新，并保留有效的其他部分。

**结果：** 两条链路均具备阶段确认、版本选择、下游失效、成片预览下载和归档的工程流程。作品可继续编辑和逻辑删除；素材与知识资料不因删除项目而被连带清空。减少返工是设计目标，实际节省的操作数与时间尚未测量。

### 3. 生成能力拆分、提示词与模型选择

**问题：** 文字、图片、视频和配音承担不同任务；统一使用隐藏默认模型，会让用户无法判断可选能力，也无法追溯结果来源。

**动作：** 按剧本、分镜、角色/场景图、镜头图和视频等阶段拆分输入与生成职责；以已确认的上游内容、参考素材和知识资料组织后续输入。确认普通用户可从公开目录选择适用模型，管理员配置仍受保护；通过协作实现模型兼容校验和实际使用记录。

**结果：** 文字、图片和相应视频模式可展示可用选项，选择可持久化并进入实际请求；阶段与素材历史保留实际模型来源，失效或不兼容选项不静默回退。此处已验证的是选择和调用合同，不宣称某候选的画质、速度或性价比已经优于另一候选。

### 4. 资料复用与生成一致性管理

**问题：** 人物设定、背景资料和参考图容易在多阶段生成中丢失，用户也难以解释某个结果采用了哪版信息。

**动作：** 确认按项目显式绑定知识库；通过协作接入资料上传、版本化、语义检索、固定约束和来源展示；将选定角色/场景图片引用到后续视觉生成，并保留人工确认和局部返修入口。

**结果：** 知识来源、使用版本、资料变化与素材引用有可追溯的工程记录。真实两镜头样片已完成，但灯塔尺度、人物合成感与信封颜色仍有偏差；RAG独立集未达标，真实资料采用效果另验。输入链路已连接，不直接声称跨镜头人物始终一致或知识不会被误用。

### 5. AIGC 质量评价与失败案例闭环

**问题：** 接口返回成功、MP4 能播放和内容质量合格是不同判断；只看自动化通过数容易掩盖跑题、角色变化、配音和检索失败。

**动作：** 以现有 D7 评价维度检查符合描述、质量可用、风格一致及内容边界，采用 1–3 分、平均不低于 2 且无 1 分项的既有要求；将故事一致性 AC07、漫剧真实样片 COMIC07、RAG08 真实资料采用与工程检查分开。对检索使用冻结数据、开发集和独立留出集，保留失败案例，不用调低标准覆盖失败。

**结果：** 当前文档明确区分“工程通过”“真实效果待验”和“独立集未达标”。RAG 开发集校准后通过，但独立留出集 Recall@5 为 0.80，H01/H07/H08 失败；这些失败仍保留。上一轮自查定位了重提收费请求、媒体编码、进程回收和预览错误残留，并补回归验证。

**本轮实际闭环：** 场景误用人物prompt带入女性形象，修正为`SETTING_PROMPT`后只重绘l1；分镜`voice_map`臆造声线ID，结构修复后再生成通过，提示词动态加入可用声线。故事灯塔尺度/人物合成感、漫画摄影背景与人物线稿风格、信封跨镜头颜色偏差继续保留，语音自然度未完成人工听审。后续按失败ID记录原输入、版本、产物、修改和复测，用旧集回归及独立新样本判断，不能因成片可播放宣称D7全优。

### 6. 执行可靠性、提效与成本意识

**问题：** 生成失败、响应丢失和进程中断可能导致重复提交、任务无法继续或反复生成；这些问题会同时影响体验和费用。

**动作：** 确认任务与事件持久化、失败可见、局部重生成及输入保留的要求；通过协作将图片下载重试与生成提交分开，付费提交结果未知时停止自动重提；为 FFmpeg 配置时限及取消回收。本轮将“继续未完成任务”和“重新生成”分开：恢复使用原始输入、模型及上游版本快照，发生变化则拒绝；有供应商任务 ID 的图片和视频先查询、下载，未知结果不盲目补提。设置可配置的全局 2 个、账号 1 个并发执行，以及平台每月 500 元、账号每月 100 元的预算上限。

**结果：** 本轮视频首镜头任务ID保存后主动终止隔离worker，跨进程恢复完成两镜头，总视频POST仅2个，无重复首镜头。实际HTTP402后充值恢复，复用第一张图，仅第二张新attempt；明确未受理可人工新提交，unknown仍禁止盲提。本轮费用按表估算9.34644元，另一次LLM超时预留0.114967元，供应商实付`null`；30条账本为28 completed、1 rejected、1 uncertain，不含Edge TTS。尚无受控效率基线、实际账单对账或商业收益，不填写节省比例。本地单worker与SQLite仍是边界，TTS不属于供应商续接。

## 五、项目经历

**AI造梦机｜AI 视频创作与项目资产管理平台**

**项目角色：** AI 产品经理 / 产品负责人
**核心维度：** 产品架构｜AI 任务编排与 HITL｜RAG 与 Context｜多模态模型与 Prompt｜评测与成本治理

### 项目概述

AI造梦机面向个人创作者和小型内容团队，提供故事短视频与漫剧的一体化创作。通过多模态模型、RAG 和项目资产管理，打通创意到成片，解决工具分散、上下文断层与素材复用难题。

### 职责描述

**负责 AI造梦机从 0 到 1 的产品设计、研发落地与商业化推进，统筹需求规划、产品架构、多模态模型策略、质量评测及成本治理。**

**【需求洞察与产品规划】** 围绕故事创作、漫剧制作与内容复用场景，拆解用户任务与创作痛点，定义 2 条主链路、3 种快捷工具的功能边界；负责 PRD、信息架构、迭代优先级及验收标准，形成以项目为核心的产品体系。

**【产品架构与 AI 任务编排】** 将两类创作任务分别建模为 6 阶段状态机，定义节点输入输出、产物依赖与推进条件；设计人工审核、内容编辑、版本选择和定向重生成的 HITL 机制，通过版本血缘与下游失效标记，保障创作可控及跨阶段内容衔接。

**【RAG 与 Context Engineering】** 搭建创作知识库，设计文档分块、Embedding 向量检索、Top-K 召回与相似度阈值；按阶段注入角色设定、固定约束、检索资料及已确认产物，配套上下文预算、引用快照与版本追溯，支撑知识复用与生成依据可查。

**【多模态模型与 Prompt 策略】** 围绕剧本、图像、视频及 TTS 配音建立模型能力适配矩阵与阶段化 Prompt 模板；将角色身份、空间关系、镜头数量、视觉风格和声线选项转化为生成约束，结合结构化输出、Schema 校验与有限重试，控制格式异常和内容偏题。

**【质量评测与数据驱动迭代】** 构建覆盖需求符合、人物一致、画面质量、镜头运动及配音字幕的 5 维评价标准；建立开发集与独立 Holdout 检索评测，结合 Recall@5、约束覆盖及 Bad Case 归因，将评审发现回流至 Prompt、检索参数与产品规则。

**【产品交付与成本治理】** 通过 AI 协作推进前后端集成、真实样片验收与版本交付，落地请求幂等、任务状态持久化及调用追溯；建立并发准入、预算预留和模型用量台账，以费用估算支撑成本分析与商业定价决策。

### 项目成果

1. 作为项目负责人，完成 AI造梦机从 **0 到 1 的产品设计与落地**，跑通创意输入、知识资料引用、剧本生成、角色场景设定、分镜、画面生成、配音字幕及成片导出的完整流程，形成故事短视频与漫剧双链路创作平台。

2. 将两类作品制作分别标准化为 **6 个创作阶段**，打通文本、图像、视频与配音能力，支持跨阶段内容继承、局部重生成和历史选版，使用户能够围绕同一作品持续修订、复用素材并完成成片制作。

3. 建立 **5 个内容质量维度、26 项知识检索评测用例**，将创作约束、人物一致性和资料引用要求转化为可检查的评价规则；通过评审、问题归因与策略调整，形成支持模型和 Prompt 持续优化的质量迭代机制。

4. 沉淀角色与场景设定、创作知识库、模型适配、Prompt 约束、素材版本及 Bad Case 分析方法，使内容资产和创作经验持续积累，并支持后续题材扩展与创作流程复用。

## 七、业务与质量指标：定义好以后再采集

当前没有足够的真实用户和受控制作基线。以下为待采集口径，不是已达到的指标或上线承诺。每份结果应带时间范围、版本、任务类型、样本数、失败/取消数和数据来源；故事与漫剧分别统计，不把两种制作难度直接合并。

| 指标 | 分子与分母 / 计算口径 | 采集与限制 |
| --- | --- | --- |
| 单集技术完成率 | 分子：在约定观察期内成功导出且通过解码/播放检查的项目数；分母：同批开始首次生成的项目数 | 失败、超时保留在分母；用户取消单列，同时报告包含取消与剔除取消的口径 |
| 单集内容验收通过率 | 分子：通过冻结质量要求的成片数；分母：进入该批完整人工评价的成片数 | 同时报技术失败数与待评数，避免只展示成功产物掩盖端到端问题；缺少评分则为待验 |
| 镜头首次质量通过率 | 分子：首轮生成并评为可用的镜头数；分母：预先选定、完成首轮视觉评审的镜头数 | 不能将返修后的结果计为首次通过；生成失败和未评镜头另报数量 |
| 角色一致性通过率 | 分子：身份、关键外观及服饰等冻结检查项全部合格的镜头对数；分母：预先定义的同角色有效镜头对数 | 评审前固定角色和镜头对；无同角色重复出镜的作品不能贡献一致性样本 |
| 漫剧语音与字幕通过率 | 分子：说话人、可懂度、文字与时间对齐均通过的对白句数；分母：抽样方案指定且完成检查的对白句数 | 句子和镜头不可混用分母；自然度人工评分单列，不能用“有音频文件”替代 |
| 人工返修率 | 分子：首次审查后至少修改一次的产物单元数；分母：完成首次审查的产物单元数 | 剧本、镜头图、对白分别统计；同一单元多次改动不重复计入，另报返修次数分布 |
| 制作耗时与提效 | 每集从确认输入到通过同一验收门槛的总历时与人工活跃时间；提效比例=(基线耗时−平台耗时)/基线耗时 | 对同一创作者、相近复杂度任务做成对比较；区分排队、等待模型与人工操作；基线为 0 或未测时不计算比例 |

| 局部重生成节省 | 对同一修改需求，完整重生成的对照费用/调用量与局部重生成的实际费用/调用量分别记录 | 未执行完整对照时只能称估算节省；不能把未调用的整个流程标价直接写成实付节省 |
| 供应商任务续接成功率 | 分子：通过已持久化任务 ID 查询或下载恢复、且未重复提交生成的任务数；分母：已提交到供应商且可观测的受控中断任务数 | 本轮已做一次真实跨进程场景，不推出长期成功率；未知、无任务ID、供应商失败另组；明确未受理后的新attempt不混入无新提交续接 |
| 并发/费用限制有效性 | 分子：按规则被正确拒绝且未新增供应商请求的超限尝试数；分母：预先构造的全部超限尝试数 | 这是保护机制测试，不是业务成功率；要包括同时提交的竞态，并验证未超限正常请求 |
| RAG 检索与采用 | Recall@5：每个有答案 case 的 gold 文档召回比例，再按 case 宏平均；内容采用：正确采用必要事实且无冲突的已评生成任务数 ÷ 需要引用资料的已评生成任务数 | 依照既有冻结评测方案；无答案、固定约束、版本/删除单列；检索分数不等于最终创作正确率 |
