造AI造梦机 PROJECT CASE
AI VIDEO CREATION · PRODUCT & DELIVERY

把创意，变成作品。也让每一步创作可检查、可修改。

AI造梦机是一款面向个人创作者和小型内容团队的 AI 视频创作平台。通过可编辑、可确认的制作流程，把创意或故事转化为故事短视频或漫剧视频。

01 / BACKGROUND

为什么做这个产品

有生成能力之后，用户仍需要组织故事、画面、声音和修改过程。项目首先解决从想法到成片的操作与衔接问题。

个人创作者常从一句创意开始，却要自行拆剧本、准备角色、生成镜头，再把图像、视频、配音和字幕串起来。一旦其中一处需要修改，很难判断应重做什么、哪些素材可以保留。

AI造梦机把过程拆成有明确产物和人工确认点的阶段。用户先判断内容是否符合意图，再进入下一步；遇到不满意的镜头或失败任务，能够定位问题、局部修改和继续创作。

把一个故事想法做出来

起点是一句创意或短篇故事。用户需要知道怎样拆成剧本、角色和可制作镜头，而不是只拿到一个难以修改的结果。

产物：默认一集的故事短视频与阶段素材

制作对白驱动的漫剧

有情节、人物关系和对白，还需要衔接漫画镜头、说话人、配音、字幕与时长。

产物：基础运镜、角色配音和中文字幕组成的 MP4

只修改不满意的部分

已有大部分可用内容，只想改一句对白或一个镜头。用户需要保留成功结果，并知道哪些下游产物受影响。

能力：局部重生成、历史选版与下游失效提示

让设定与资料持续可用

复用人物设定、世界观和创作材料时，减少反复输入，并能核对本次生成用了哪版资料。

能力：项目知识库、来源记录与本人素材复用
目标用户与上述场景是当前的产品定位。制作时间、单片成本、真实用户留存等业务结果，仍需按相同任务与验收标准采集，尚未形成可对外宣称的提升比例。

快捷工具独立提供文艺短视频、角色动作短片、图片配音口播，服务于一次性短视频需求，不混入漫剧阶段。

创作前端

当前架构为单后端 worker、本地数据库与本地检索索引。它是带人工确认点的创作工作流；多机调度、对象存储迁移和生产容量仍需独立建设与验收。

02 / OWNERSHIP

个人主导，AI 协作落地

产品方向、范围和验收判断由本人负责，AI 辅助方案拆解、开发和重复性验证。职责描述对应实际工作方式。

本人主导的工作

  • 定位与需求：确定目标用户、创作场景和双主链路，明确本期产物与优先级。
  • 交互与视觉：选择页面方向，走查导航、创作路径与作品管理，提出具体修改。
  • 产品规则：确认默认一集、公开模型选择、管理员权限和阶段确认方式。
  • 阶段验收：判断内容是否符合创作意图、视觉是否可用，决定继续、返修或保留待验。

AI 与工程系统协作

  • 方案分析：整理用户问题，核对需求、接口和现有代码之间的关系。
  • 实现与集成：辅助编写前后端代码、提示词、模型适配和技术文档。
  • 工程检查：验证状态、权限、请求合同、媒体格式和已知失败场景。
  • 过程记录：保存输入、模型来源、历史版本、依赖失效与测试证据。
AI 生成候选按确认输入生产内容与媒体
→
人检查与选择剧本、分镜、素材和最终成片
→
系统保存与衔接记录选版，标记受影响下游

项目经历以个人主导与 AI 协作为边界，不将协作生成代码表述为全部手写，也不虚构外部研发团队、商业客户交付或大规模用户访谈。

03 / CORE WORK

六项核心职责

把每项能力放回具体问题，说明采取了什么动作，以及目前可以核实的结果。

01

用户问题定义与需求范围

问题
功能逐步增加，入口、主流程和辅助工具的关系容易混乱。
动作
按用户、场景、问题和产物重写需求；确定故事与漫剧双主链，明确默认一集、共用知识库、快捷工具用途及权限。
结果
形成可检查的阶段输入、产物、确认点和验收条件。漫剧使用独立阶段与视频交付规则；产品市场匹配仍待真实用户验证。
02

流程设计与可控人机协作

问题
直接生成最终结果难定位错误；局部修改后，下游可能继续使用过期素材。
动作
定义分阶段检查、编辑、选版和重生成规则；协作接入版本、引用依赖与失效提示，允许按角色、场景或镜头定向更新。
结果
两条链路具备确认、选版、下游失效和成片归档的工程闭环。作品支持继续与逻辑删除；实际节省的操作数与时间尚未测量。
03

生成能力、提示词与模型选择

问题
各阶段的文字、画面、视频需求不同；隐藏默认模型使用户缺少选择，也难追溯来源。
动作
拆分生成职责，以已确认上游内容、参考图和知识资料组织输入；开放兼容模型目录，保留管理员配置权限和实际调用记录。
结果
用户选择能持久化并进入实际请求，历史产物可查模型来源。不兼容或失效选项不静默回退；模型画质和性价比仍需专门对比评测。
04

资料复用与生成一致性

问题
人物设定、世界观和参考图容易在多阶段流转中丢失，资料版本也难核对。
动作
按项目显式绑定知识库；接入上传、版本化、检索、固定约束与来源展示；将选定角色和场景图引用到后续视觉生成。
结果
知识来源、使用版本和素材引用形成可追溯记录。真实两镜头成片已完成，但尺度、人物合成感和信封颜色仍有偏差；RAG 独立集未达标，资料采用另验。
05

AIGC 质量评价与 bad case 闭环

问题
接口成功、MP4 能播放与内容合格是不同结果，单看工程测试会遗漏跑题、角色变化和声音问题。
动作
分开工程检查、D7 人工评价、故事一致性 AC07、漫剧 COMIC07 和 RAG08 采用评价；冻结检索集，保留开发集与独立集失败记录。
结果
修正场景误用人物提示词与声线 ID 臆造，保留原错误和复测记录。样片工程闭环通过，内容质量需迭代；语音自然度未听审。独立检索 0.80 与 H01/H07/H08 失败仍保留。
06

执行可靠性与成本控制

问题
中断、响应丢失和失败重试可能导致重复生成、任务无法继续和额外费用。
动作
区分继续未完成任务与重新生成；冻结原输入，已知任务查询下载，未知提交不盲重提；明确未受理的步骤可人工新 attempt，正常预算。
结果
真实跨进程恢复成功，两镜头仅 2 次视频 POST，无首镜头重提。402 后充值复用成功图，仅被拒绝图新 attempt。默认并发 2/1、月预算 500/100 元；实际成本节省未测。

AI造梦机

AI 产品经理 / 产品负责人

AI 视频创作与项目资产管理平台

核心维度：产品架构｜AI 任务编排与 HITL｜RAG 与 Context｜多模态模型与 Prompt｜评测与成本治理

项目概述

AI造梦机面向个人创作者和小型内容团队，提供故事短视频与漫剧的一体化创作。通过多模态模型、RAG 和项目资产管理，打通创意到成片，解决工具分散、上下文断层与素材复用难题。

职责描述

负责 AI造梦机从 0 到 1 的产品设计、研发落地与商业化推进，统筹需求规划、产品架构、多模态模型策略、质量评测及成本治理。

【需求洞察与产品规划】围绕故事创作、漫剧制作与内容复用场景，拆解用户任务与创作痛点，定义 2 条主链路、3 种快捷工具的功能边界；负责 PRD、信息架构、迭代优先级及验收标准，形成以项目为核心的产品体系。

【产品架构与 AI 任务编排】将两类创作任务分别建模为 6 阶段状态机，定义节点输入输出、产物依赖与推进条件；设计人工审核、内容编辑、版本选择和定向重生成的 HITL 机制，通过版本血缘与下游失效标记，保障创作可控及跨阶段内容衔接。

【RAG 与 Context Engineering】搭建创作知识库，设计文档分块、Embedding 向量检索、Top-K 召回与相似度阈值；按阶段注入角色设定、固定约束、检索资料及已确认产物，配套上下文预算、引用快照与版本追溯，支撑知识复用与生成依据可查。

【多模态模型与 Prompt 策略】围绕剧本、图像、视频及 TTS 配音建立模型能力适配矩阵与阶段化 Prompt 模板；将角色身份、空间关系、镜头数量、视觉风格和声线选项转化为生成约束，结合结构化输出、Schema 校验与有限重试，控制格式异常和内容偏题。

【质量评测与数据驱动迭代】构建覆盖需求符合、人物一致、画面质量、镜头运动及配音字幕的 5 维评价标准；建立开发集与独立 Holdout 检索评测，结合 Recall@5、约束覆盖及 Bad Case 归因，将评审发现回流至 Prompt、检索参数与产品规则。

【产品交付与成本治理】通过 AI 协作推进前后端集成、真实样片验收与版本交付，落地请求幂等、任务状态持久化及调用追溯；建立并发准入、预算预留和模型用量台账，以费用估算支撑成本分析与商业定价决策。

项目成果

  1. 作为项目负责人，完成 AI造梦机从 0 到 1 的产品设计与落地，跑通创意输入、知识资料引用、剧本生成、角色场景设定、分镜、画面生成、配音字幕及成片导出的完整流程，形成故事短视频与漫剧双链路创作平台。
  2. 将两类作品制作分别标准化为 6 个创作阶段，打通文本、图像、视频与配音能力，支持跨阶段内容继承、局部重生成和历史选版，使用户能够围绕同一作品持续修订、复用素材并完成成片制作。
  3. 建立 5 个内容质量维度、26 项知识检索评测用例，将创作约束、人物一致性和资料引用要求转化为可检查的评价规则；通过评审、问题归因与策略调整，形成支持模型和 Prompt 持续优化的质量迭代机制。
  4. 沉淀角色与场景设定、创作知识库、模型适配、Prompt 约束、素材版本及 Bad Case 分析方法，使内容资产和创作经验持续积累，并支持后续题材扩展与创作流程复用。
