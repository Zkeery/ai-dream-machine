- 决策类型：能不能上。对象：Agent、Prompt、恢复执行器组合。业务任务：故事/漫剧阶段执行。

- 不把离线测试、可解析JSON或单张图片成功等同于创作质量提升、生产成功率或供应商稳定性保证。

## 门槛

- R1：ID、角色和依赖由代码编译；模型不能改变工具权限或跨阶段执行。
- R2：格式校验有字段反馈；允许的本地保守恢复必须留下可见记录，不能冒充模型审稿通过。
- R3：恢复复用原输入版本、计划、已完成动作和产物；已成功媒体POST重复次数为0。
- R4：未知媒体提交不自动重发；无法恢复时说明准确原因，不把已收到但格式错误的回复误报未知请求。
- R5：没有知识库时不调用空检索；步骤数、调用数和费用均有边界。
- R6：运行清单包含成功和失败，每条绑定case、版本、次数、耗时、费用、Trace；缺少必需真实运行时结论为待补齐，不能宣称验收通过。

## 覆盖与报告

离线必须覆盖：正常计划、缺资料、格式修复耗尽、非法工具、生成前失败、生成成功后审稿失败、进程中断、纯文本恢复、媒体恢复、未知提交、并发重复继续、输入变化、预算耗尽。机器规则通过明确正反例校准，不建立主观综合分或虚构多人试标。

真实批次分开报告：文本控制与模拟生成工具的重复运行，仅验证Agent控制；实际图片请求验证供应商协议及图片产物。每批运行前冻结清单、重复次数、代码与Prompt哈希、模型及参数、费用上限。图片样本需要实际查看，自动文件校验不能替代视觉检查。真实输出未执行或未复核时写待补齐。
