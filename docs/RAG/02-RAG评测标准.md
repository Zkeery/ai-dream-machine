# AI造梦机 · RAG 评测标准

> 更新：2026-10-06  
> 来源：从 [RAG评测方案](RAG评测方案.md)「目标和边界」「评分规则与校准」拆出；门槛值与两份 fixture 的 `configuration` 一致。原方案未改，口径冲突时以原方案为准。

## 1. 评测对象

| 项目 | 冻结值 |
| --- | --- |
| 评测版本 | 开发集 `rag-creation-zh-v1`；留出集 `rag-creation-zh-holdout-v1` |
| 对象 | 创作知识库的**检索层**，不评 LLM 回答、图像或视频效果 |
| 评测单位 | 一条查询及其返回的文档块、版本、固定约束和错误状态 |
| 输入 / 输出 | 输入为合成资料、账号、选定库、查询，答案标签不传给检索器；输出为 Top-5 普通命中、版本、固定约束、耗时 |
| 重复与重试 | 每条查询 2 次，0 次自动重试 |
| 费用与数据 | 本地 Embedding，0 次付费模型调用；临时目录与合成账号，不碰用户知识库 |
| 不在范围 | 生成模型效果、人工审美、付费 API、生产容量、真实资料分布泛化、提示注入后的 LLM 行为 |

## 2. 门禁

| 类型 | 指标 | 线 |
| --- | --- | --- |
| 通过线 | 有答案 case 宏平均 Recall@5 | ≥ 0.85 |
| 通过线 | 必要固定约束覆盖率 | 100% |
| 通过线 | 关键 case（`critical: true`）通过率 | 100% |
| 否决线 | 跨账号或跨选定库泄漏、召回被删资料或旧版本、丢失必要约束、空查询返回普通命中、无答案强召回 | 任一出现即否决 |

## 3. 评分规则

全部为确定性断言（ID、原文、版本），**不使用 LLM Judge**。

| 规则 | 计算方法 | 正例 / 反例 |
| --- | --- | --- |
| RET01 Recall@5 | 前 5 个普通命中的不同 document_id 与 gold 的交集 ÷ gold 数量；gold 非空时才计入均值 | R07 两份都召回得 1；只召回一份得 0.5 |
| CON01 必要约束覆盖 | 必要约束原文须出现在固定约束区，相似命中不能顶替 | R10 返回“无机动车”原文通过 |
| SEC01 范围与归属 | 普通命中与约束均来自本次允许的本人库；越权须被拒绝 | 返回 private_code 即否决 |
| VER01 版本与删除 | 命中版本等于当前版本且含新事实；删除项不得出现 | R17 命中 v2“二十七岁、银色”通过 |
| EMP01 空与无答案 | 普通命中数为 0；固定约束可独立存在，不算答案 | H07、H08 有普通命中即失败 |
| DATA01 证据完整 | 用例无缺失，模型 / 版本 / hash / 查询 / 命中 / 耗时 / 异常齐全；异常不可补分 | 漏跑则 STOP |

## 4. 判定输出

证据 JSON `summary.decision` 中实际出现的取值：`PILOT_FAIL`、`LOCAL_ENGINEERING_FAIL`、`LOCAL_ENGINEERING_PASS`。安装失败、模型不可用、接口错误或漏跑按方案记为 STOP，不降级为关键词搜索或假 Embedding。

## 5. 评测纪律

1. 看到结果后不降低门槛；gold、评分规则或门槛变化须升级评测版本，旧证据保留。
2. 模型、切分或检索策略变化须绑定新候选配置、新运行批次。
3. 开发集调参后的成绩不能当作泛化证据，须另用冻结的留出集验证，且不得追着留出集调参。
4. gold 有分歧记 NEED_REVIEW 并冻结结论，不主观补分。

## 6. 与 PRD 验收项的关系

| PRD 项 | 本标准覆盖情况 |
| --- | --- |
| RAG02 按中文创作问题检索 | 本标准主体（RET01 + DATA01） |
| RAG03 固定约束与无答案 | 检索层部分由 CON01、EMP01 覆盖；预算超限等路径另由后端测试覆盖 |
| RAG04 账号 / 选库隔离 | 检索层部分由 SEC01 覆盖；API 权限另由后端测试覆盖 |
| RAG06 更新、删除资料 | 检索层部分由 VER01 覆盖 |
| RAG08 真实生成质量对照 | **不在本标准内**，需无 RAG / 有 RAG 真实对照，待验 |

## 7. 充分性拒答补充标准（2026-10-06）

检索层原标准不变。拒答层另计：

| 规则 | 计算方法 |
| --- | --- |
| REF01 无答案不注入 | `expect_empty_hits` 用例的普通 `sources` 必须为空（可有 `rejected_sources`） |
| REF02/03 拒答标记 | 同域无答案应为 `status=insufficient` 且 `adequacy.sufficient=false`；仅约束命中且无普通命中时 `matched`/`no_match` 亦可 |
| REF05/06 有答案不误拒 | 有 gold 文档的用例应保持 `matched` 且 `sufficient=true`，误拒率单独汇报 |

评测脚本：`backend/scripts/evaluate_rag_refusal.py`；证据文件名含 `refusal` 与日期，不覆盖旧检索批次。
