# AI造梦机 · RAG 模型选型

> 更新：2026-10-06  
> 来源：[RAG技术与数据设计](RAG技术与数据设计.md)「选型与运行」、[PRD](../PRD/PRD.md) 第 10、12 节范围、`backend/app/services/knowledge_retrieval.py`；对比实测见 [05-RAG模型评测](05-RAG模型评测.md) 与 `docs/evidence/RAG/rag-eval-model-*-20261006*.json`。  
> 决策：**继续使用本地 FastEmbed + `BAAI/bge-small-zh-v1.5` + Qdrant 本地模式**。本轮已做可达候选对比；结论依据数据，不是“未对比所以默认”。

## 1. 选型约束

| 约束 | 来源 |
| --- | --- |
| 资料以中文创作文本为主 | 资料范围：`.md` / `.txt` / 文本 PDF |
| 本地 CPU 运行，检索测试不产生云端费用 | 技术设计「验证与费用」 |
| 保持前端 3030、后端 8030 两个服务，不新增 Docker 服务或云资源 | 技术设计「选型与运行」 |
| 与用户所选的生成模型解耦，换 LLM 不换 Embedding | 适用范围说明 |
| 来源可追溯：原文、版本在 SQLite，向量只做检索 | 技术设计「选型与运行」 |

## 2. 本轮对比摘要

| 候选 | 状态 | 校准后留出集 Recall@5 | 检索 p50（留出校准后） | 权重体积 | 备注 |
| --- | --- | ---: | ---: | ---: | --- |
| `BAAI/bge-small-zh-v1.5` | 实测 | 0.80 | ≈ 3.8 ms | ≈ 90 MB | 基线；开发集校准阈值 0.49 |
| `BAAI/bge-base-zh-v1.5` | **不可测** | — | — | — | FastEmbed 不支持 |
| `BAAI/bge-m3` | **不可测** | — | — | — | FastEmbed 不支持 |
| `jinaai/jina-embeddings-v2-base-zh` | 实测（替代候选） | 0.80 | ≈ 14.5 ms | ≈ 611 MB | FastEmbed 可用中文替代；校准阈值 0.38 |

两者校准后留出集召回相同，均未过 0.85；H01 / H07 / H08 均未过。jina 更慢、更大，且分数尺度不同，不能沿用 0.48。

## 3. 选型结果

| 部分 | 选型 | 原因 | 代价 / 边界 |
| --- | --- | --- | --- |
| 文本向量 | FastEmbed + `BAAI/bge-small-zh-v1.5`，512 维 | 满足中文 + 本地 CPU + 零费用；对比 jina 后留出集召回持平但体积与延迟显著更优 | 首次下载约 90MB；输入控制在模型 512 token 内，切片上限 380 字 |
| 向量存储 | Qdrant Python client 本地磁盘模式 | 无需单独部署；支持按 owner / library / version 过滤 | **只能单 worker** |
| 资料与版本 | SQLite `knowledge.db` | 权威记录，便于版本、归属与快照 | — |
| 生成模型 | 用户所选兼容 LLM，经既有 AIHubMix 网关 | 沿用现有网关与 JSON 校验 | 命中片段和固定约束随生成请求发送至网关 |
| 重排 | 生产不设独立 Reranker | PRD 列为本版不做；2026-10-06 离线实验显示混合检索 / BGE 重排可修好 H01、留出集 Recall@5 提至 1.00，但修不了 H07/H08，暂未接入生产 | 见 [08](08-RAG检索流水线与重排说明.md) §4 |

**不切换到 jina 的理由（数据）：** 留出集 Recall@5 无提升（同为 0.80）；检索约慢 5 倍；权重约大 7 倍；需新建 768 维集合并全量重建索引。

**暂不引入 bge-base-zh / bge-m3 的理由：** 当前依赖栈（FastEmbed）无法加载；若要评测需更换 Embedding 运行时，属于新的工程决策，需单独立项。

## 4. 阈值

生产配置仍为 `SCORE_THRESHOLD = 0.48`（见 `knowledge_retrieval.py`）。本轮在开发集上扫到 0.49 亦可使开发集全过，与 0.48 差异很小，留出集表现相同；**不因留出集结果回调阈值**。若日后改阈值，须新开证据批次并保留旧文件。

## 5. 切换条件与成本

| 项 | 说明 |
| --- | --- |
| 触发重新选型 | 新冻结留出集上 Recall@5 持续低于 0.85，且归因于 Embedding 表达力不足；或必须使用 FastEmbed 不支持的模型因而更换运行时 |
| 切换成本 | 集合按维度与模型绑定（当前 `creative_knowledge_bge_zh_v1`、512 维）；换维度需新建集合并重建全部索引 |
| 切换纪律 | 新模型单独跑批次，旧证据保留；对比流程与本轮一致：临时库、开发集校准、留出集只验证 |
