# AI造梦机 · RAG 检索流水线与重排说明（LLM / EM / RA）

> 更新：2026-10-06  
> 来源：`backend/app/services/knowledge_store.py`、`backend/app/services/knowledge_retrieval.py`、[RAG技术与数据设计](RAG技术与数据设计.md)、[PRD](../PRD/PRD.md) 不做范围；评测证据见 `docs/evidence/RAG/rag-eval-hybridrerank-*-20261006.json` 与 `rag-eval-hybridrerank-master-summary-20261006.json`。  
> **生产现状**：Embedding + 向量检索 + **答案充分性拒答** + LLM 生成；**无**独立 Reranker；**无**混合检索（开关默认关）。  
> **实验现状**：2026-10-06 混合/重排离线评测未接入；同日拒答已接入生产，证据见 `rag-eval-refusal-*-20261006.json`。

## 1. 三段现状（生产）

| 环节 | 本版实现 | 说明 |
| --- | --- | --- |
| EM（Embedding） | FastEmbed + `BAAI/bge-small-zh-v1.5`，512 维，余弦相似度 | 本地 CPU；查询取前 2000 字符做向量 |
| RA（Rerank） | **无**（生产） | 排序完全按 Qdrant 余弦分数；PRD 将“独立 Reranker”列为本版不做 |
| LLM（生成） | 用户所选兼容 LLM，经既有 AIHubMix 网关 | 资料以 JSON 数据注入用户消息；系统提示要求忽略资料中的指令 |

## 2. 生产流水线

| 步骤 | 规则 | 参数 |
| --- | --- | --- |
| 1. 解析 | UTF-8 文本、pypdf 提取文字；扫描件不做 OCR | 单文件 5MB；文本 ≤ 200000 字符 |
| 2. 切分 | 先按空行 / Markdown 标题分段；长段按 380 字切，优先在 220–380 字之间的句末断开，相邻片段重叠 60 字 | 每版本 ≤ 800 片 |
| 3. 入库 | 向量写入 Qdrant 本地集合 `creative_knowledge_bge_zh_v1`，payload 带 owner / library / version | 单 worker |
| 4. 查询校验 | 查询不能为空且 ≤ 20000 字符；条数 1–10，默认 5 | 违规返回 422 |
| 5. 过滤检索 | 按 owner + 选定库 + 有效版本三重过滤；先核对索引片数与资料一致，不一致返回 503 | Top 5，阈值 0.48 |
| 6. 组装上下文 | 固定约束整份先放入（不检索）；普通片段按分数依次加入，超出总预算即停止，不截断片段；编号 K1、K2… | 约束 ≤ 6000 字；总预算（含约束）12000 字 |
| 7. 充分性拒答 | 先 `classify_knowledge_query`：`creative` 有普通命中则跳过 LLM 并视为充分；`fact` 才经 AIHubMix 结构化判定。不充分则普通命中进 `rejected_sources`，`status=insufficient` | 判定失败/超时降级为不充分；预算类错误上抛。round2 留出集误拒率 0 |
| 8. 状态 | `matched` / `no_match` / `insufficient`；warnings 提示未覆盖事实；前端来源面板展示拒答资料 | 检索故障返回 503，不当作空结果继续 |
| 9. 生成 | 先保存检索快照（含 adequacy / rejected_sources）到 execution_inputs，再调用 LLM；系统提示禁止从 rejected_sources 编造事实 | — |

## 3. 无 Reranker / 无混合检索时的已知影响

| 证据 | 影响 |
| --- | --- |
| H01 正确资料诊断分 0.4534，低于阈值 0.48 被过滤 | 意译问法漏召回 |
| H07 / H08 同域无答案分别以 0.6508 / 0.7552 被召回 | 相关性排序判断不了“资料里有没有答案” |
| 阈值 0.48 下 R03、R06、R07、R09、R17 出现 0.48–0.55 的非 gold 命中 | 片段多时可能挤占 12000 字预算 |

## 4. 2026-10-06 离线实验（已评测，未接入生产）

实验约束：不改项目源码、不写真实知识库；参数只在开发集调，留出集只测一次；不调用付费云端 API。

### 4.1 方案

| 方案 | 做法 | 开发集调参 |
| --- | --- | --- |
| 基线 | 现网：`bge-small-zh-v1.5`，阈值 0.48，Top5 | 不调 |
| 混合检索 | 字符 n-gram BM25（2–3 元 + 汉字单字）+ 向量召回 TopN，RRF 融合（k∈{30,60}，N∈{10,20}） | 网格后选用 N=20，k=60（三者目标值相同） |
| 重排 | 向量 Top20（阈值放开）→ `BAAI/bge-reranker-base` → Top5；阈值在开发集扫描 | 冻结 **thr=-5.0**（开发集首次同时达到 Recall=1 / Critical=1 / R12 空命中） |
| 混合+重排 | RRF 候选 Top20 → 同上重排与阈值 | 同 thr=-5.0 |

另：曾用英文 `Xenova/ms-marco-MiniLM-L-6-v2` 做流水线冒烟；其中文分数与无答案题不可分，**不作中文质量结论**。证据见 `rag-eval-hybridrerank-rerank-summary-20261006.json`。

### 4.2 结果对比

| 方案 | 开发集 Recall@5 | 开发集 Critical | 留出集 Recall@5 | 留出集 Critical | H01 | H07 | H08 | 检索 p50 / p95（ms） |
| --- | ---: | ---: | ---: | ---: | --- | --- | --- | --- |
| 基线 | 1.00 | 1.00 | 0.80 | 0.33 | 失败 | 失败 | 失败 | 3.4 / 4.2 |
| 混合检索 | 1.00 | 0.89（R12 失败） | **1.00** | 0.33 | **通过** | 失败 | 失败 | 3.4 / 4.3 |
| BGE 重排 thr=-5 | **1.00** | **1.00** | **1.00** | 0.33 | **通过** | 失败 | 失败 | 109 / 154 |
| 混合+BGE 重排 thr=-5 | **1.00** | **1.00** | **1.00** | 0.33 | **通过** | 失败 | 失败 | 45 / 98 |

约束覆盖在上述批次中均为 1.0。重排模型体积约 **1.06GB**，首次加载约 **1.0–1.1s**。

### 4.3 H01 / H07 / H08

| 题 | 基线 | 混合 | BGE 重排 | 说明 |
| --- | --- | --- | --- | --- |
| H01 意译漏召回 | 失败（诊断分 0.4534&lt;0.48） | 通过 | 通过（重排分约 2.36） | 关键词/BM25 或放宽初召回+重排均可找回 |
| H07 同域无答案 | 失败（召回陆遥档案） | 失败 | 失败（重排分约 0.98 &gt; -5） | 同域人物档案仍被判相关 |
| H08 同域无答案 | 失败（召回青禾杯说明） | 失败 | 失败（重排分约 -1.56 &gt; -5） | 同域产品说明仍被判相关 |

开发集上 thr=-5 能清掉**跨域**无答案 R12（木星气压），但留出集同域无答案 H07/H08 的重排分仍高于该阈值；若把阈值抬到能挡住 H07（&gt;0.98），开发集多道 gold 题会掉召回。说明：**排序/重排解决不了“同域但资料无答案”**，需要答案充分性或拒答机制。

### 4.4 结论与是否接入生产

1. **混合检索（BM25 + 向量 RRF）**：成本低（无新模型）、耗时与基线接近，留出集 Recall@5 从 0.80→1.00 并修好 H01；开发集会让跨域无答案 R12 变脏。若接入，需另补拒答/空结果策略，或接受该权衡。  
2. **BGE 重排**：可在开发集同时保住召回与 R12 空命中，也能修好 H01，但 **修不好 H07/H08**，并带来约 1GB 模型与数十到百余毫秒延迟。  
3. **拒答已接入生产**（见 §6）。混合检索在拒答可兜住 R12 时仍抬高误拒，**继续不接入**。  
4. 证据文件均带方案名与日期 `20261006`，未覆盖旧批次。

## 5. 引入生产的触发条件（仍适用）

1. 新冻结留出集上仍有「正确资料已进入未过滤候选、但被阈值或 Top5 挤出」类失败，且混合检索实测稳定收益。  
2. 真实资料规模增大后，Top5 被同域非 gold 占满或上下文预算频繁触顶。  
3. 另有可独立评测的拒答/答案充分性方案，能覆盖 H07/H08 类 Badcase。

## 6. 答案充分性拒答（已接入生产）

| 项 | 说明 |
| --- | --- |
| 开关 | `KNOWLEDGE_ADEQUACY_ENABLED`（默认 `1`） |
| 位置 | `build_context` 组装普通命中之后、返回快照之前 |
| 模型 | 现有 `LLMClient` / AIHubMix；计入 `model_usage` 与预算预留 |
| 降级 | 超时、格式失败等 → `sufficient=false` + `degraded=true`；预算类错误上抛 |
| 产物字段 | `status`、`adequacy`、`rejected_sources`、`warnings`、`retrieval_mode` |
| 留出集 | H07 / H08 正确拒答；schema 别名修复后回归仍通过 |
| 混合检索 | 代码可开 `KNOWLEDGE_HYBRID_RETRIEVAL_ENABLED`，默认 `0`，本次评测不建议打开 |

触发条件 §5 第 3 条（拒答方案）已满足；意译漏召回（H01/RB03）仍待混合检索或其它召回增强，且须先把误拒压到可接受再开。
