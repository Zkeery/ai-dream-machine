# 内容安全结果侧拦截 技术开发文档

> 配套：PRD V1.0 第 7.3 节（内容红线：提示词侧 + 生成结果侧双向拦截）。当前只实现了提示词侧（SAFETY_RULE），本文档补结果侧。

## 一、目标与范围

- **目标**：对生成出的图片/视频做"结果侧"内容审查，命中红线（真人肖像、侵权 IP、违法低俗）时拦截并给出可读原因，不产出违规内容。
- **范围**：
  - 新增视觉审查器（VLM qwen3-vl 系列），审查生成图片；视频取首帧审查（MVP 先审首帧，逐帧审查后续）。
  - 在角色/场景图、参考图、视频片段生成后接入审查；命中则阶段失败、不落违规产物。
  - 可开关（`CONTENT_REVIEW_ENABLED`，默认开）；命中即拦，不自动放行。
- **不做**：提示词侧已有约束不重复实现；视频逐帧审查、申诉复核流程（后续）。

## 二、实现要点

1. 新增 `app/models/vlm_client.py`：OpenAI 兼容视觉调用（`qwen3-vl-flash`，`.env` 可配 `VLM_MODEL`），输入本地图片 base64 + 审查指令，返回结构化判定。
2. 新增 `app/services/content_review.py`：
   - `review_image(path) -> {safe, reason}`：调 VLM，要求返回 JSON `{safe: bool, reason: str}`。
   - 结果强校验（safe 必须是布尔），解析失败按"待人工复核"处理——**不静默放行**，记为拦截失败并报错。
3. 编排器接入：
   - 角色/场景图、参考图生成后逐张 `review_image`；视频片段生成后取首帧 `review_image`。
   - 命中红线 → 抛 `CONTENT_REVIEW_FAILED`（可读原因），阶段置 failed，不写违规产物。
4. 配置：`.env` 增加 `CONTENT_REVIEW_ENABLED`（默认 "1"）、`VLM_MODEL`（原默认 qwen3-vl-flash；2026-10-11 起代码默认改为 qwen3-vl-plus，因 qwen3-vl-flash 在 AIHubMix 实测返回 404 model not exist，仍可用 `VLM_MODEL` 覆盖）；关闭开关时跳过审查（本地调试用，上线默认开）。

## 三、测试计划（mock，不调真实 VLM）

| --- | --- |

| 回归 | 全量测试保持通过；关闭开关时行为不变 |
