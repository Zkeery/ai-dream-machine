## 3. 技术选择
- 框架与版本：Next.js（App Router）+ React 19 + TypeScript strict（Node 24 环境）
- 样式与组件策略：Tailwind CSS + CSS 语义变量；组件先原生 + 轻量自建，暂不引入组件库
- 数据请求与状态策略：集中式 API 客户端（`lib/api`）；状态用 React 自带（useState/useEffect/Context），暂不引入 TanStack Query / Zustand
- 流式通信策略：SSE 用 **Fetch Streaming**（后端 SSE 需 `Authorization: Bearer` 头，原生 EventSource 带不了自定义头）
- 表单方案：原生受控表单（表单简单，暂不引入 React Hook Form）
- 测试方案：Vitest + React Testing Library；核心闭环用 Playwright 后续补
- 部署环境：本地开发（前端 3030 / 后端 8030），通过 Next `rewrites` 把 `/api/*` 代理到后端

## 4. Agent 状态
后端状态 → 前端统一状态映射：

| 后端字段 | 值 | 前端状态 |
| --- | --- | --- |
| 会话 status | idle/running/stage_completed/session_completed/failed | 对应 idle/running/waiting/succeeded/failed |
| 任务 status | pending/running/completed/failed | queued/running/succeeded/failed |

- 等待用户确认：6 阶段流程每阶段完成后"确认进入下一阶段"（POST /sessions/{id}/continue）
- 重试：阶段失败可重新"生成当前阶段"；短管线任务失败可重建任务
- 恢复：通过 session_id / task_id 重新向后端查询真实状态，刷新后从 URL 或列表恢复
- 断线：SSE 断开后按任务 ID 查询状态，不盲目重复创建

## 6. 偏离本手册的地方
- **鉴权**：手册默认 HttpOnly Cookie；本项目后端已用 `Authorization: Bearer` + 令牌，前端存 `localStorage`（因 SSE 需带自定义头）。MVP 先保持 Bearer，**生产上线前迁移 HttpOnly Cookie**。
- **未引入** TanStack Query / Zustand / React Hook Form / shadcn：当前复杂度未触发，避免过早引入。
- **Playwright**：核心 E2E 后续补，先以真实浏览器人工验收为主。
