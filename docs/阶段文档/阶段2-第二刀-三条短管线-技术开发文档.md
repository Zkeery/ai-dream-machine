# 阶段 2 技术开发文档｜第二刀：三条一次性短管线

> 配套文档：PRD V1.0（第 2.1、2.4、3.3 节）、《技术适配声明》《架构方案》、第一刀/第三刀手册。
> 本文档只覆盖第二刀（3 条一次性短管线 + 任务后台执行）。数据库、并发分镜仍为后续刀，本刀不得提前实现。

---

## 一、目标与范围

- **交付范围**：3 条一次性短管线（文艺短视频、动作迁移、数字人口播）+ 任务后台执行 + SSE 进度订阅 + 账号隔离（继承第三刀）。
- **形态**：一次输入 → 后台执行 → 前端 SSE 订阅进度 → 出片，中间无人工停点；失败给可读原因并可重试。
- **验收标准**（对齐 PRD 2.4、3.3）：
  1. 三条管线各自跑通输入→产物，产物落盘可导出
  2. 任务创建后立即返回，后台执行，前端能订阅进度直到 done/error 收尾
  3. 失败返回可读原因，可重新创建任务重试
  4. 任务与产物归属账号（继承第三刀隔离：只能看自己的任务）
  5. mock 测试全过；真实模型能力如实标注「待验」，不冒充
- **明确不做**：数据库（多实体）、并发分镜、嘴型同步的真实数字人、专业剪辑、会员付费。

## 二、任务模型与存储（延续文件 + JSON，不引入数据库）

| 数据 | 文件 | 结构 |
| --- | --- | --- |
| 短管线任务 | `data/tasks/{task_id}.json` | `{task_id, type, owner_id, status, input, result, error, created_at, updated_at}` |

- `type ∈ {"literary_video", "motion_transfer", "talking_head"}`。
- `status ∈ {"pending", "running", "completed", "failed"}`。
- `result`：产物路径与元数据（成片、中间文件、文案/音频列表）。
- 进度事件为内存队列（进程重启后不恢复，正在跑的任务标为 failed）；任务最终结果落盘可恢复。

## 三、API 设计（全部继承第三刀鉴权与隔离）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/tasks` | 创建任务：body 含 `type` 与对应输入；后台启动执行；返回 `task_id` |
| GET | `/api/tasks` | 列出当前用户任务（按 `created_at` 倒序） |
| GET | `/api/tasks/{id}` | 查询任务状态与结果（仅本人，他人 404） |
| GET | `/api/tasks/{id}/stream` | SSE 订阅进度：`progress*` → `done/error` 收尾 |
| GET | `/api/tasks/{id}/export` | 下载成片（仅本人） |

- 任务创建即持久化（`pending`），后台 asyncio 任务推进到 `running → completed/failed`。
- SSE 必须 `done` 或 `error` 收尾（沿用第一刀 `_sse_run` 契约）。

## 四、三条管线实现

### 4.1 文艺短视频 `literary_video`
- **输入**：`text`（灵感或完整文案）、可选 `style`、`ratio`。
- **处理**：
  1. 若文案 ≤ 30 字视为灵感 → LLM 扩写成 2~4 句；否则按完整文案直接用。
  2. 文案按句号/换行分句，最多 8 句。
  3. 每句：文生图（`image.text_to_image`，prompt = 该句 + 风格）→ `image/{task_id}/i.jpg`；TTS（`tts.synthesize`）→ `video/{task_id}/i.mp3`。
  4. FFmpeg：每句「图片 + 对应音频」合成片段，再拼接成最终成片 `video/{task_id}/final.mp4`。
- **产物**：成片 mp4、文案、逐句图片与音频。

### 4.2 动作迁移 `motion_transfer`
- **输入**：`character_image`（角色图上传）、`motion_video`（动作视频上传）、`prompt`（提示词）。
- **处理**：
  1. FFmpeg 提取动作视频首帧 → `image/{task_id}/motion_frame.jpg`（存档，作为动作参考）。
  2. 角色图 → 参考图生视频（`video.image_to_video(mode="reference")`）+ 提示词 → `video/{task_id}/final.mp4`。
- **如实标注**：MVP 用「角色参考图 + 提示词」生成，动作视频仅提取首帧存档，**未做像素级动作迁移**；真实迁移能力待模型侧核验后再增强，不冒充已实现。

### 4.3 数字人口播 `talking_head`
- **输入**：`person_image`（人物图上传）、`script`（口播文案）。
- **处理**：
  1. TTS 配音（`tts.synthesize`）→ `video/{task_id}/voice.mp3`。
  2. FFmpeg：人物图 + 配音合成视频 → `video/{task_id}/final.mp4`（静态人物图 + 配音）。
- **如实标注**：MVP 为「静态人物图 + 配音」，**无嘴型同步**；真实嘴型同步待后续模型，不冒充已实现。

## 五、模型与配置

- 复用现有客户端：`LLMClient`（qwen3.5-plus）、`ImageClient`（qwen-image-2.0）、`VideoClient`（wan2.7-i2v/r2v）、`TTSClient`（edge-tts）。
- 上传文件校验沿用 `path_security`（图片 jpg/png/webp ≤25MB；视频 mp4 ≤100MB）。
- 动作迁移/数字人口播的模型能力边界在真实冒烟时逐项核验，不预设通过。

## 六、最小验收界面更新

- 左侧新增「短管线」区：三个入口（文艺短视频 / 动作迁移 / 数字人口播），各自表单 + 上传。
- 任务列表显示状态；点击任务订阅进度（SSE）；完成后可下载成片。
- 继承第三刀登录与账号隔离。

## 七、测试计划（mock，不调真实模型）
