## 当前适配结果（2026-10-04）

AI造梦机是一款面向个人创作者和小型内容团队的AI视频创作平台，帮助用户将创意或故事，通过可编辑、可确认的制作流程，转化为故事短视频或漫剧视频。

| 事项 | 当前实现与边界 |
| --- | --- |
| 双主链路 | 故事短视频与漫剧分别编排，创建后不互换；故事默认 1 集，漫剧首期单集、默认 9:16 |
| 共用能力 | 邀请码账号、SQLite、作品/素材、任务与版本、知识库；知识库按项目独立绑定，三种快捷工具归短视频 |
| 数据与删除 | SQLite 元数据及执行账本、本地产物文件；本人非运行作品可逻辑删除，阻断旧链接与快照恢复，不物理清理共享资料 |
| 模型与权限 | 普通用户按能力公开名单选模型，执行与产物保存实际来源；设置/沙盒仅管理员访问，注册不自动提权，密钥不进前端 |
| 媒体能力 | 漫剧用漫画镜头、在线 Edge TTS、FFmpeg 基础运镜与字幕合成；故事后期仍为片段拼接，不承诺完整配音字幕或口型 |
| 验证 | 模型选择工程与页面验收已记录；最新版 AC07、COMIC07、RAG08 真实生成质量待验，RAG 留出集未通过 |
| 部署 | 本地前端 3030 / 后端 8030；云资源、云数据库及备份方案尚未实施 |

当前合同详见 [技术接入方案](技术接入方案-汇报评审版.md)、[漫剧开发说明](漫剧双链路技术适配与开发说明.md)、[用户模型选择](用户模型选择技术适配.md)和 [RAG 技术与数据设计](../RAG/RAG技术与数据设计.md)。本次仅同步文档，不新增厂商、费用或真实模型调用。

## 1. 产品形态判断

- **产品类型与核心任务**：分阶段确认的多媒体创作 Agent——从一句创意到一部完整成片（AI 短片/短剧）。
- **核心交互**：分阶段确认（6 阶段状态机，每阶段产物可查看、可修改后重生成）+ 3 条一次性后台管线。
- **开发路径**：**纵向切片（路径 B）**。理由：人工确认、图片/视频预览、任务进度与恢复本身就是本产品核心体验的一部分，不能把 UI 留到最后当"展示壳"。
- **当前阶段范围**：阶段 2 = 后端 MVP 第一刀（6 阶段主流程 + 产物留存 + 可导出，本地单机）。短管线、登录为后续刀。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.12 + FastAPI | 默认后端栈；与线上运行时 veFaaS native-python3.12 一致 |
| Pydantic 数据校验 | 校验接口入参与模型结构化输出（剧本/分镜/角色均为结构 JSON） |
| Web 前端（Next.js + TS + Tailwind） | PRD 未指定终端，默认 Web；正式前端在阶段 3 |
| Git + 项目内 .env | 密钥外置、版本可追溯（强制底线） |
| 模型调用用官方 SDK / 兼容接口 | 通义 DashScope、火山方舟 ARK 均为官方 SDK |

## 3. 触发的按需模块

| 模块 | 由哪条需求触发 | 当前阶段是否引入 |
| --- | --- | --- |
| 大图片/视频/生成文件 | 角色图、分镜、视频片段、成片 | ✅ 本地文件目录存储（不塞数据库） |
| 长耗时任务与并发 | 视频生成单片段 1~2 分钟 | ✅ 后台任务 + 进度订阅（SSE） |
| 需要逐步展示模型内容 | 阶段生成进度 | ✅ SSE，且以 done/error 收尾 |
| 多实体关系/账户/事务 | 第三刀多人（邀请码+账号隔离） | ❌ 暂缓到第三刀（见第 4 节） |
| 数据库 | 单用户 + 图片视频文件为主 | ❌ 暂缓，用带 schema 版本的文件清单 |
| 音视频后处理 | 拼接、配音、字幕 | ✅ FFmpeg（已装 9.0.2）+ TTS |
| 知识库/RAG | 无检索需求 | ❌ 不引入 |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 何时重新评估 |
| --- | --- | --- | --- | --- |
| SQLite + SQLAlchemy | 文件清单（JSON，带 schema 版本 + 原子写入） | MVP 单用户、资产以图片/视频文件为主、无复杂筛选 | 无法做复杂查询/并发事务，但对第一刀无碍 | 第三刀做多人/账号隔离时迁移数据库 |
| 关系数据库 | 同上 | 同上 | 同上 | 同上 |
| 立即做登录/账号隔离 | 暂缓到第三刀 | PRD 已定分阶段（D6） | 第一刀仅本地单机 | 第三刀 |

## 5. 强制底线检查

- **密钥与隐私**：✅ 通过——业务密钥只进项目 `.env`（gitignore），不在前端/对话/日志回显；上传素材本地留存、可删除、用途告知（PRD 7.1）
- **数据与任务可恢复**：✅ 计划通过——会话/阶段/任务状态持久化到文件（JSON），重启可恢复；人工确认点持久化
- **输入输出校验**：✅ 计划通过——上传文件校验格式/真实类型/大小/安全文件名；模型输出用 Pydantic 结构校验，失败可重试
- **错误与日志边界**：✅ 计划通过——接口错误统一 `{"error":{"code","message"}}`，不泄露堆栈；日志不记密钥/完整用户文档；SSE 以 done/error 收尾
- **内容安全红线**：✅ 计划通过——禁止生成真人肖像/侵权 IP/违法内容，提示词侧 + 结果侧双向拦截（PRD 7.3）
- **测试与真实模型验收**：mock 自动化测试先行（无 Key 不阻塞开发）；进入验收前由产品经理提供真实 Key，跑真实冒烟并用 5~10 条样例定 D7 验收标准
