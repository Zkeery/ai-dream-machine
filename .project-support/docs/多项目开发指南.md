# 多项目开发指南

本仓库把“需求 → 架构 → 开发 → 验收 → 上线”放进同一流程。共享规则和蓝图维护一份，每个产品的需求、代码、配置、依赖和运行结果全部归入自己的项目目录。

## 目录与归属

```text
项目开发必备文档/
├── AGENTS.md、CLAUDE.md、README.md
├── docs/                         # 共享 PRD 模板、三份手册、本指南
├── tools/agent-blueprint/         # 完整蓝图引擎、17 个组件、脚手架、原有测试
├── scripts/                      # 创建项目与按项目运行蓝图
├── templates/project/            # 不含业务代码和真实配置的新项目模板
└── projects/
    └── 项目名/
        ├── AGENTS.md、CLAUDE.md、README.md、project.json
        ├── .env                  # 业务配置，不入 Git
        ├── .env.blueprint        # 蓝图模型配置，不入 Git
        ├── .blueprint-venv/       # 本项目蓝图依赖环境，不入 Git
        ├── backend/              # 本项目后端、测试、requirements、.venv
        ├── frontend/             # 本项目前端、package、锁文件、node_modules
        ├── data/、logs/           # 本项目运行数据，不入 Git
        └── docs/
            ├── PRD/              # 需求和原始附件
            ├── 项目状态.md
            ├── 阶段文档/         # 已确认的技术适配、架构决策、开发计划
            ├── blueprint-runs/   # 按 plan/audit 和任务名分开的真实运行结果
            └── evidence/         # 已验收证据
```

`backend/`、`frontend/`、环境和数据目录在实际需要时创建；模板不会提前引入技术栈。工程采用一个 Git 仓库管理多个业务目录，业务运行相互隔离，不是多个独立 Git 历史或操作系统沙箱。单独拆分成 Git 仓库时，需显式带走所需共享规则与工具并修复相对引用。

以上是新项目的默认布局。已有项目可在自己的 `AGENTS.md` 中明确版本归档路径，后续文档和脚本统一沿用该布局。AI万物伙伴将技术文档与证据集中在 `docs/PRD/版本/Vx.y/`，具体入口见[项目文档导航](../projects/AI万物伙伴/docs/README.md)；不另建重复的 `docs/阶段文档/` 和 `docs/evidence/`。

## 创建和继续项目

在仓库根目录执行（也可以直接让 AI 执行）：

```sh
python3.12 scripts/projects.py create "我的新项目"
python3.12 scripts/projects.py list
```

创建命令生成项目说明、配置模板、规则入口、状态和文档目录，分配仓库内不重复的前后端端口；遇到同名项目拒绝覆盖。端口是约定，不是系统级占用锁，启动前仍须检查外部程序是否占用。不要同时从多个终端创建项目；创建完成后可分别打开不同项目开发。

继续开发时单独打开 `projects/项目名/`，或明确告诉 AI “继续项目 X”。优先按用户指定项目和当前工作目录定位，不通过共享文件切换项目。所有进度只更新该项目 `docs/项目状态.md`。

## PRD、蓝图与开发如何衔接

1. **需求**：用共享 `docs/PRD/PRD模板.md` 访谈并生成项目 PRD；也可参考蓝图需求八问。PRD 与附件只放在本项目。
2. **架构**：先读 PRD 和已有代码，判断固定工作流还是自主 Agent。蓝图可从点子或 PRD 推导架构；将适用的结论纳入本项目《技术适配声明》，标明待确认项和采用/不采用原因。
3. **开发**：遵守项目阶段与现有契约，按需参考蓝图组件。蓝图默认选用 Agent Loop/工具调用，不代表所有产品都需要；七层架构也不等于七个部署服务。
4. **迭代检查**：按需反向审计当前项目。反推需求只作为草稿；用户确认的 PRD 是对照依据，不由代码自动改写。
5. **验收上线**：仍按三份手册、真实测试和证据包推进，蓝图评分或审稿结果不能替代业务验收。

规则或建议冲突时：用户当前明确要求优先；共享规则约束工程底线，项目 PRD、决策台账和已发布接口约束业务与兼容性；蓝图仅提供设计建议。发现实际矛盾时记录并解决，不能自动引入额外模块或推翻既有实现。

## 运行蓝图

### 无独立模型配置时

当前 AI 可读取 `tools/agent-blueprint/使用引导.md` 和相关内容，按手册分析。将结果写入本项目 `docs/阶段文档/`，注明“当前 AI 按手册分析，未运行模型管线”，不伪造结构化结果或独立模型审稿。

### 离线检查入口

以下命令在仓库根目录执行，不安装依赖、不调用模型。Python 需 3.10+，本机可用 `python3.12`：

```sh
python3.12 scripts/blueprint.py --project "我的新项目" plan --idea "帮助用户整理资料" --mock
python3.12 scripts/blueprint.py --project "我的新项目" audit --mock
```

mock 是占位演示，结果只写本项目 `.runtime/blueprint-mock/`，不作为正式方案交付。

### 真实程序推导

在仓库根目录为所选项目创建独立工具环境：

```sh
python3.12 -m venv "projects/我的新项目/.blueprint-venv"
"projects/我的新项目/.blueprint-venv/bin/python" -m pip install -r tools/agent-blueprint/requirements.txt
```

将该项目 `.env.blueprint.example` 复制为 `.env.blueprint`（已有文件不可覆盖），明确填写凭证与 `MODEL_ID`。引擎目前使用 Anthropic 协议；业务项目的 OpenAI 兼容 Key/地址不能直接混用。不要为了整合目录更换业务模型。

```sh
"projects/我的新项目/.blueprint-venv/bin/python" scripts/blueprint.py \
  --project "我的新项目" plan --input "docs/PRD/PRD.md" --run "初版架构"

"projects/我的新项目/.blueprint-venv/bin/python" scripts/blueprint.py \
  --project "我的新项目" audit --prd "docs/PRD/PRD.md" --run "迭代检查"
```

`--input`、`--prd`、`--target` 一律相对所选项目根目录，不能指向其他项目。Word/PDF 先由 AI 提取成 UTF-8 文本并由用户核对。审计默认整个业务项目，也可 `--target backend` 缩小范围；不扫描整个共享仓库。

正式结果位于 `docs/blueprint-runs/plan/初版架构/` 或 `docs/blueprint-runs/audit/迭代检查/`。扫描器排除 `blueprint-runs`、本地数据、日志及原有环境/缓存目录，避免历史报告混入新的代码检查。默认自动生成唯一任务名；指定已有任务名必须显式 `--resume`。续跑使用原项目、原任务、原输入路径，输入内容变化由引擎重新计算。

入口忽略终端继承的 `ANTHROPIC_*` 与 `MODEL_ID`，只读取本项目 `.env.blueprint`。默认最多 16 次调用、400000 token，可用 `--max-calls` / `--max-tokens` 调整；这是调用与 token 护栏，不是人民币金额保证。审稿不通过仍是待修订草稿，不能仅凭命令退出成功认定完成。

## 防止项目相互影响

- 每个项目独立依赖清单、虚拟环境、前端锁文件和 `node_modules`；不在仓库根目录装一套业务依赖供所有项目使用。
- 数据库和文件路径由项目根目录解析，不能依赖启动时恰巧位于某个目录；不跨项目共用数据库、上传目录或日志。
- 不把一个项目的 `.env` 导出到公共终端后用于另一个项目。业务启动脚本读取自身配置；为不同项目使用独立终端。
- 端口写在各自 `project.json`，新建前扫描既有配置；实现服务时须显式采用分配端口，不能仅写配置而仍硬编码默认端口。
- 云端部署使用各自服务、数据库、存储与环境变量。目录隔离不自动创建或隔离云资源，部署阶段再逐项落实。
- 业务任务不修改共享工具。共享工具升级作为单独维护变更记录版本和测试结果，不自动覆盖各业务项目代码；原蓝图说明中的独立运行命令不用于本仓库业务任务。
